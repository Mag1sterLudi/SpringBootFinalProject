# ADR-003. Подбор номера по times_booked

Статус - принято

## Контекст

При автоподборе брони должны распределяться по номерам равномерно, чтобы не было номеров,
которые постоянно простаивают.

## Решение

- `rooms.times_booked` хранит число действующих броней номера. Он меняется в той же транзакции,
  что и блокировка слота (+1) или её снятие (-1), поэтому совпадает с таблицей блокировок.
- Кандидаты - номера с `available = true`, у которых нет активной блокировки, пересекающей
  период с `startDate` по `endDate`. День выезда одного гостя может быть днём заезда другого.
- Порядок - `times_booked ASC, id ASC`. Сортирует БД (индекс `idx_rooms_times_booked`), и
  booking-service сортирует ещё раз сам (`RoomRecommendationService`), чтобы не зависеть от
  реализации hotel-service.
- booking-service перебирает до 5 кандидатов - если номер успели занять, пробует следующий.

## Последствия

- Номера с наименьшим числом броней заполняются первыми, разница в `times_booked` со временем
  выравнивается. Это видно в `/api/hotels/{id}/statistics` (`averageTimesBooked`, `idleRoomIds`).
- Цена и пожелания гостя в порядке не учитываются. Если нужно, выборку можно сузить фильтрами
  `type`, `minCapacity`, `maxPrice`.

# ADR-002. JWT HS256 с общим секретом, каждый сервис проверяет токен сам

Статус - принято

## Контекст

Нужны JWT с ролями USER и ADMIN, срок жизни 1 час, и проверка токена в каждом сервисе, а не только
на шлюзе. Отдельного сервера авторизации (Keycloak и т.п.) нет, регистрация и вход по заданию
находятся в booking-service.

## Решение

- Токены выпускает booking-service через `JwtEncoder` (Nimbus), алгоритм HS256.
  Claims: `sub` (логин), `uid` (id пользователя), `roles`, `iss`, `iat`, `exp`, `jti`.
- Секрет общий для всех сервисов, задаётся через `JWT_SECRET` (не меньше 256 бит).
- Gateway и оба сервиса настроены как OAuth2 Resource Server и сами проверяют подпись, срок и
  издателя. Gateway не пускает анонимные запросы (кроме регистрации, входа и health-проверки), роли проверяют сервисы:
  по URL и через `@PreAuthorize` на контроллерах.
- Для вызовов hotel-service booking-service выпускает себе токен с ролью `INTERNAL` на 5 минут.
  Плюс внутренние эндпойнты вообще не маршрутизируются через Gateway.
- 401 и 403 отдаются в формате `ApiError` (`RestSecurityErrorHandler`, `JsonSecurityErrorHandler`).

## Последствия

- Работает локально без дополнительной инфраструктуры.
- Минус - любой сервис, у которого есть секрет, может выпустить токен.
- Отозвать токен раньше чем через час нельзя.
